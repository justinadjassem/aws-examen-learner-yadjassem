Big Data & IA — Architecture IoT sur AWS

Plateforme serverless AWS pour l'ingestion et le traitement en temps reel de donnees transmises par des capteurs IoT industriels. Les flux HTTP POST sont traites par AWS Lambda (Python 3.11), stockes dans un Data Lake S3 partitionne et un Feature Store DynamoDB, le tout accelere par Amazon CloudFront.

Infrastructure as Code (SAM)

L'ensemble de l'infrastructure est definie dans un template AWS SAM (template.yaml) et deployee automatiquement via CloudFormation. Le deploiement se fait en une seule commande : make deploy.

S3 Data Lake

Le bucket S3 est entierement prive (PublicAccessBlock active). Les donnees brutes y sont stockees au format JSON.

Partitionnement S3

Strategie de partitionnement temporel pour faciliter les requetes analytiques futures :

CloudFront — CDN Ingestion

Une distribution CloudFront est placee devant l'API Gateway pour accelerer la collecte globale des donnees IoT. Le cache est desactive (TTL=0) car chaque requete POST doit atteindre la Lambda. Seul le header Content-Type est forward vers l'origine.

CloudFront — Documentation (OAC)

Le bucket S3 de documentation est entierement prive. L'acces public se fait uniquement via une distribution CloudFront avec un Origin Access Control (OAC) qui signe chaque requete avec SigV4. Toute tentative d'acces direct au bucket S3 retourne 403 Access Denied.

template.yaml — OACYAML
1DocOAC:
2 Type: AWS::CloudFront::OriginAccessControl
3 Properties:
4 OriginAccessControlConfig:
5 SigningBehavior: always
6 SigningProtocol: sigv4
7 OriginAccessControlOriginType: s3
